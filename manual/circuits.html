Circuits¶

On this page you can find all the information needed to build a circuit using MIMIQ. Every useful function will be presented below, accompanied by an explanation of their purpose and examples of use.

What is a circuit and what are instructions¶

A quantum circuit, similar to a classical circuit, represents a sequence of quantum gates applied to qubits, which are the carriers of quantum information. Quantum circuits are essential for designing quantum algorithms. The complexity of a quantum circuit is typically measured by two key metrics: width and depth. Width refers to the number of qubits in the circuit, while depth indicates the maximum number of sequential gates applied to any single qubit.

Here is a representation of a simple GHZ circuit on 4 qubits:

from mimiqcircuits import *
>>> ghz = Circuit()
>>> ghz.push(GateH(), 0)
1-qubit circuit with 1 instructions:
└── H @ q[0]

>>> ghz.push(GateCX(), 0, range(1, 4))
4-qubit circuit with 4 instructions:
├── H @ q[0]
├── CX @ q[0], q[1]
├── CX @ q[0], q[2]
└── CX @ q[0], q[3]

>>>
>>> ghz.draw()
                ┌─┐
         q[0]: ╶┤H├─●──●──●────────────────────────────────────────────────────────────╴
                └─┘┌┴┐ │  │
         q[1]: ╶───┤X├─┼──┼────────────────────────────────────────────────────────────╴
                   └─┘┌┴┐ │
         q[2]: ╶──────┤X├─┼────────────────────────────────────────────────────────────╴
                      └─┘┌┴┐
         q[3]: ╶─────────┤X├───────────────────────────────────────────────────────────╴
                         └─┘

In this representation, each qubit is depicted by a horizontal line labeled q[x], where x is the qubit’s index. The circuit is read from left to right, with each ‘block’ or symbol along a line representing an operation applied to that specific qubit.

Circuits & Instructions in MIMIQ¶

MIMIQ implements a circuit using the Circuit structure, in essence this structure is a wrapper for a vector of Instruction to be applied on the qubits in the order of the vector. Since it is a vector a circuit can be manipulated as such, for example you can use for loops to iterate over the different instructions of the circuit, do vector comprehension or access all common vector attributes such as the length.

An Instruction is composed of the quantum operation to be applied to the qubits, and the targets on which to apply it. There are many types of quantum operations, as discussed in the unitary gates, non-unitary operations and other pages of the manual. The targets can be qubits, as well as boolean or complex number vectors where classical information can be stored. You will generally not need to interact with the Instruction class directly (for exceptions, see special operations), but it is useful to understand how MIMIQ works.

See the following sections to learn how to add operations to your circuit.

Registers: quantum/classical/Z-register¶

Before explaining how to build a circuit it is important to make a distinction between the different target registers your operations will be applied to.

The circuits in MIMIQ are composed of three registers that can be used by the instructions: * The Quantum Register: Used to store the qubits state. Most of the operators in MIMIQ will interact with the quatum register. When printing or drawing a circuit (with the function draw() ) the quantum registers will be denoted as q[x] with x being the index of the qubit in the quantum register. * The classical register: Used to store the bits state. Some gates will need to interact with classical bits (ex: Measure ) and the state of the classical bits is stored in the classical register, which is a vector of booleans. When printing or drawing a circuit the classical register will be denoted by the letter c. * The Z-register: Used to store the result of some specific operations when the expected result is a complex number (ex: ExpectationValue ). The Z-register is basically a vector of complex numbers. When printing or drawing a circuit the Z-Register will be denoted by the letter z.

For the three registers operators can be applied on an arbitrary index starting from 0 (as does Python in general contrary to Julia). When possible you should always use the minimal index available as going for an arbitrary high index N will imply that N qubits will be simulated and might result in a loss of performance and will also make the circuit drawing more complex to understand.

Here is a circuit interacting with all registers:

from mimiqcircuits import *
>>> # create empty circuit
>>> circuit = Circuit()

>>> # add X to the first qubit of the Quantum register
>>> circuit.push(GateX(), 0)
1-qubit circuit with 1 instructions:
└── X @ q[0]


>>> # compute Expectation value of qubit 1 and store complex number on the first Z-Register
>>> ev = ExpectationValue(GateZ())
>>> circuit.push(ev, 0, 0)
1-qubit, 1-zvar circuit with 2 instructions:
├── X @ q[0]
└── ⟨Z⟩ @ q[0], z[0]


>>> # Measure the qubit state and store bit into the first classical register
>>> circuit.push(Measure(), 0, 0)
1-qubit, 1-bit, 1-zvar circuit with 3 instructions:
├── X @ q[0]
├── ⟨Z⟩ @ q[0], z[0]
└── M @ q[0], c[0]


>>> # draw the circuit
>>> circuit.draw()
                ┌─┐┌─────────┐┌──────┐
         q[0]: ╶┤X├┤   ⟨Z⟩   ├┤  M   ├─────────────────────────────────────────────────╴
                └─┘└────╥────┘└───╥──┘
                        ║         ║
                        ║         ║
         c:    ═════════╬═════════╩═════════════════════════════════════════════════════
                        ║         0
         z:    ═════════╩═══════════════════════════════════════════════════════════════
                        0

As you can see in the code above the indexing of the different registers always starts by the quantum register. If your operator interacts with the three registers the index will have to be provided in the following order: #. Index of the qantum register. #. Index of the classical register. #. Index of the z-register.

Be careful when writing information to the z-register or to the classical register as the information can be easily overwritten if the same index is used multiple times. For example if you measure two different qubits and store both in the same classical bit the results of the sampling will only report the last measurement.

To retrieve information on the number of element of each register you can use the num_qubits() , num_bits() and numz_vars() .

>>> circuit.num_qubits(), circuit.num_bits(), circuit.num_zvars()
(1, 1, 1)

In the following sections you will learn in details how to build a circuit in MIMIQ.

Creating a circuit¶

The first step in executing quantum algorithm on MIMIQ always consists in implementing the corresonding quantum circuit, a sequence of quantum operations (quantum gates, measurements, resets, etc…) that acts on a set of qubits. In MIMIQ we always start by defining an empty circuit

>>> circuit = Circuit()

There is no need to give any arguments. Not even the number of qubits, classical or Z-registers is necessary as it will be directly inferred from the operations added to the circuit.

Adding Gates¶

Once a circuit is instantiated operations can be added to it. To see the list of gates available head to OPERATIONS , GATES , NOISECHANNELS and GENERALIZED or enter the following command in your Python session:

help(Gates)

To know more about the types of operations you can use in a circuit head to the unitary gates, non-unitary operations, noise, symbolic operations and special operations pages.

push¶

To add gates to circuits in Python we will mainly be using the push() method. The arguments needed by push() can vary, but in general it expects the following: #. The circuit to add the operation to. #. The operator to be added. #. As many targets as needed by the operator (qubits/bits/zvars).

For instance you can add the gate X by simply running the following command:

>>> circuit.push(GateX(), 0)
1-qubit circuit with 1 instructions:
└── X @ q[0]

The text representation `H @ q[0]` informs us that there is an instruction which applies the Hadamard gate to the qubit of index 1.

Some gates require multiple target qubits such as the CX gate. Here is how to add such a gate to the circuit:

>>> circuit = Circuit()
>>> circuit.push(GateCX(), 0, 1)
2-qubit circuit with 1 instructions:
└── CX @ q[0], q[1]

This will add the gate GateCX using the qubit number 1 as the control qubit and number 2 as the target qubit in the circuit.

push specifics¶

push() is very versatile, it can be used to add multiple operators to multiple targets at once using iterators.

To add one type of gate to multiple qubits use:

>>> circuit = Circuit()
>>> circuit.push(GateX(), range(0, 11))
11-qubit circuit with 11 instructions:
├── X @ q[0]
├── X @ q[1]
├── X @ q[2]
├── X @ q[3]
├── X @ q[4]
├── X @ q[5]
├── X @ q[6]
├── X @ q[7]
├── X @ q[8]
├── X @ q[9]
└── X @ q[10]

This will add one X gate on each qubit from number 1 to 10.

Insert¶

You can also insert an operation at a given index in the circuit using the insert() function:

>>> circuit = Circuit()
>>> circuit.push(GateX(), 1)
2-qubit circuit with 1 instructions:
└── X @ q[1]

>>> circuit.push(GateZ(), 1)
2-qubit circuit with 2 instructions:
├── X @ q[1]
└── Z @ q[1]


>>> # Insert the gate at a specific index
>>> circuit.insert(2, GateY(), 1)
2-qubit circuit with 3 instructions:
├── X @ q[1]
├── Z @ q[1]
└── Y @ q[1]

>>> circuit
2-qubit circuit with 3 instructions:
├── X @ q[1]
├── Z @ q[1]
└── Y @ q[1]

This will insert GateY applied on qubit `1` at the second position in the circuit.

Append¶

To append one circuit to another you can use the append() function:

>>> # Build a first circuit
>>> circuit1 = Circuit()
>>> circuit1.push(GateX(), range(1, 4))
4-qubit circuit with 3 instructions:
├── X @ q[1]
├── X @ q[2]
└── X @ q[3]


>>> # Build a second circuit
>>> circuit2 = Circuit()
>>> circuit2.push(GateY(), range(1, 4))
4-qubit circuit with 3 instructions:
├── Y @ q[1]
├── Y @ q[2]
└── Y @ q[3]


>>> # Append the second circuit to the first one
>>> circuit1.append(circuit2)
>>> circuit1
4-qubit circuit with 6 instructions:
├── X @ q[1]
├── X @ q[2]
├── X @ q[3]
├── Y @ q[1]
├── Y @ q[2]
└── Y @ q[3]

This will modify circuit1 by appending all the operations from circuit2.

This function is particularly useful for building circuits by combining smaller circuit blocks.

Decompose¶

Most gates can be decomposed into a combination of U and CX gates, the decompose() function extracts such decomposition from a given circuit:

>>> circuit = Circuit()
>>> circuit.push(GateX(), 0)
1-qubit circuit with 1 instructions:
└── X @ q[0]


>>> # decompose the circuit
>>> circuit.decompose()
1-qubit circuit with 1 instructions:
└── U(pi, 0, pi, 0.0) @ q[0]

decompose() also takes a target basis from mimiqcircuits.decomposition. For example, CliffordTBasis rewrites the circuit into Clifford and T gates. Rotations by multiples of \(\pi/4\) are decomposed exactly. Other rotations are approximated by GridSynthRewrite, by default to an operator-norm error of \(10^{-10}\) each, and the rotations argument selects a different tolerance or rule:

>>> from mimiqcircuits.decomposition import CliffordTBasis, GridSynthRewrite
>>> circuit = Circuit()
>>> circuit.push(GateRZ(0.123), 0)
1-qubit circuit with 1 instruction:
└── RZ(0.123) @ q[0]


>>> # approximate the rotation to 1e-10 with Clifford+T gates
>>> fine = circuit.decompose(CliffordTBasis())

>>> # a looser tolerance gives a shorter circuit
>>> shorter = circuit.decompose(CliffordTBasis(rotations=GridSynthRewrite(epsilon=1e-4)))
>>> len(shorter) < len(fine)
True

Ancillas¶

By default a decomposition only uses the qubits of the operation it decomposes. Some operations have much shorter decompositions when they may use other qubits as well. The bases CanonicalBasis, CliffordTBasis and QASMBasis take three options for that, all off by default:

  • borrow=True lets a decomposition borrow qubits of the circuit that the operation does not act on. A borrowed qubit can be in any state, even entangled, and the decomposition leaves it exactly as it found it.

  • max_ancillas=k lets it add up to k clean ancillas: new qubits, numbered after those of the circuit, that start in \(|0\rangle\) and are returned to \(|0\rangle\). An ancilla freed by one operation is reused by the next one.

  • allow_measurement=True, together with max_ancillas, lets it undo some steps by measuring an ancilla instead of with more gates. The circuit must have classical bits; the measurements write one extra bit after them.

Today these options apply to multi-controlled X gates, where the gain is largest. With four controls and Clifford+T as the target:

>>> c = Circuit()
>>> c.push(Control(4, GateX()), 0, 1, 2, 3, 4)
5-qubit circuit with 1 instruction:
└── C₄X @ q[0:3], q[4]

>>> c.push(GateH(), 5)
6-qubit circuit with 2 instructions:
├── C₄X @ q[0:3], q[4]
└── H @ q[5]


>>> def tcount(circuit):
...     return sum(isinstance(i.operation, (GateT, GateTDG)) for i in circuit)

>>> # without help, the decomposition needs small rotations, approximated
>>> tcount(c.decompose(CliffordTBasis()))
1627

>>> # borrowing qubit 5 gives Toffolis, which are exact
>>> tcount(c.decompose(CliffordTBasis(borrow=True)))
70

>>> # two clean ancillas hold the AND of the first controls
>>> d = c.decompose(CliffordTBasis(max_ancillas=2))
>>> tcount(d)
23
>>> ancillas(d)
[6, 7]

The decomposition marks each clean ancilla with an AncillaAlloc where it starts being used and an AncillaFree where it is back in \(|0\rangle\). These annotations do nothing when the circuit runs, but they tell later passes, and ancillas(), which qubits are ancillas. check_ancillas() checks that they are consistent.

With wrap=True, a gate that uses clean ancillas becomes a call to a GateDecl with the ancillas as its last targets, and num_ancillas says how many of them there are. The markers go around the call:

>>> w = decompose(c, CanonicalBasis(max_ancillas=2), wrap=True)
>>> w
8-qubit circuit with 6 instructions:
├── AncillaAlloc @ q[6]
├── AncillaAlloc @ q[7]
├── mimiq_C4X() @ q[0:4,6:7]
├── AncillaFree @ q[6]
├── AncillaFree @ q[7]
└── mimiq_H() @ q[5]

>>> w[2].operation.num_ancillas
2

With measurements, each AND costs 4 T gates and is undone for free:

>>> c.push(Measure(), 4, 0)
6-qubit, 1-bit circuit with 3 instructions:
├── C₄X @ q[0:3], q[4]
├── H @ q[5]
└── M @ q[4], c[0]

>>> m = c.decompose(CliffordTBasis(max_ancillas=3, allow_measurement=True))
>>> tcount(m)
12
>>> m.num_bits()
2

A gate declaration cannot measure, so with wrap=True such a gate becomes a call to a BlockDecl instead. Its bit is the extra one, and identical gates share the declaration:

>>> decompose(c, CliffordTBasis(max_ancillas=3, allow_measurement=True), wrap=True)
9-qubit, 2-bit circuit with 9 instructions:
├── AncillaAlloc @ q[6]
├── AncillaAlloc @ q[7]
├── AncillaAlloc @ q[8]
├── mimiq_C4X @ q[0], q[1], q[2], q[3], q[4], q[6], q[7], q[8], c[1]
├── AncillaFree @ q[6]
├── AncillaFree @ q[7]
├── AncillaFree @ q[8]
├── H @ q[5]
└── M @ q[4], c[0]

Ancillas are meant for exporting circuits and counting resources. A simulator gains nothing from them: it applies a multi-controlled gate directly, and every extra qubit makes the simulation larger.

Dependency graph (DAG) view¶

A circuit is stored as an ordered list of instructions, but many of those instructions are independent: they act on different qubits and could run in any relative order. dag() exposes this structure as a CircuitDAG, a dependency graph whose vertices are the instruction positions 0 .. n-1 and whose edges u -> v mean instruction v depends on u (they share a qubit, bit, or z-variable and u is the most recent earlier instruction on that wire). This is useful for analysing or reordering a circuit — for example to find which gates can be fused or run in parallel.

>>> c = Circuit()
>>> c.push(GateH(), 0)
1-qubit circuit with 1 instruction:
└── H @ q[0]

>>> c.push(GateCX(), 0, 1)
2-qubit circuit with 2 instructions:
├── H @ q[0]
└── CX @ q[0], q[1]

>>> c.push(Measure(), 0, 0)
2-qubit, 1-bit circuit with 3 instructions:
├── H @ q[0]
├── CX @ q[0], q[1]
└── M @ q[0], c[0]

>>> dag = c.dag()
>>> dag
CircuitDAG(vertices=3, edges=2)
>>> dag.edges()
[(0, 1), (1, 2)]

The graph can be sorted into a topological order, or you can iterate the circuit’s instructions directly in dependency order with traverse_by_bfs() (layer by layer) or traverse_by_dfs():

>>> topological_sort_by_bfs(dag)
[0, 1, 2]
>>> [str(inst) for inst in traverse_by_bfs(c)]
['H @ q[0]', 'CX @ q[0], q[1]', 'M @ q[0], c[0]']

With the optional networkx dependency installed (pip install mimiqcircuits[graph]), to_networkx() returns the same graph as a networkx.DiGraph for drawing or further analysis.

push_expval(hamiltonian, *qubits, firstzvar=None)

Append the computation of the expectation value of a Hamiltonian.

Called as a method, circuit.push_expval(hamiltonian, *qubits). For each term \(c_j P_j\) it appends an ExpectationValue of \(P_j\) into z-variable firstzvar + j and scales it by \(c_j\) with Multiply, then sums them all with Add, so that z-variable firstzvar ends up holding

\[\langle \psi | H | \psi \rangle = \sum_j c_j \langle \psi | P_j | \psi \rangle.\]

The other z-variables keep the value of each scaled term. The state is not changed.

Parameters:

  • hamiltonian (Hamiltonian) – The Hamiltonian to evaluate.

  • *qubits (int) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly hamiltonian.num_qubits() of them.

  • firstzvar (int, optional) – First z-variable to use. Defaults to the first unused one, circuit.num_zvars().

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian.

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("ZZ"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * ZZ @ q[0,1]
>>> # Hamiltonian qubits 0 and 1 are circuit qubits 1 and 2
>>> c.push_expval(h, 1, 2)
3-qubit, 1-zvar circuit with 3 instructions:
├── ⟨ZZ⟩ @ q[1:2], z[0]
├── z[0] = 1.0 * z[0]
└── z[0] = 0.0 + z[0]

push_lietrotter(h, qubits, t, steps)

Append the first-order (Lie-Trotter) time evolution under a Hamiltonian.

Called as a method, circuit.push_lietrotter(h, qubits, t, steps). It approximates \(e^{-iHt}\), for \(H = \sum_{j=1}^m c_j P_j\), by

\[e^{-i H t} \approx \left[ \prod_{j=1}^m e^{-i c_j P_j \Delta t} \right]^n,\]

with \(n\) = steps and \(\Delta t = t / n\). The error per step is of order \(\Delta t^2\) and vanishes when the terms commute.

One step is declared once as a gate named trotter with parameter \(\Delta t\), holding one Pauli rotation per term (GateRX, GateRZZ, RPauli, …). The circuit gets steps calls to it.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian.

See also

push_suzukitrotter(), push_yoshidatrotter(), GateDecl

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("ZZ"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * ZZ @ q[0,1]
>>> # evolve for t = 1 in 3 steps of 1/3
>>> c.push_lietrotter(h, (0, 1), t=1.0, steps=3)
2-qubit circuit with 3 instructions:
├── trotter(0.3333333333333333) @ q[0:1]
├── trotter(0.3333333333333333) @ q[0:1]
└── trotter(0.3333333333333333) @ q[0:1]
push_suzukitrotter(h, qubits, t, steps, order=2)

Append the time evolution under a Hamiltonian with a Suzuki-Trotter formula.

Called as a method, circuit.push_suzukitrotter(h, qubits, t, steps, order). It approximates \(e^{-iHt}\) with the Suzuki product formula of the given even order, whose error per step is of order \(\Delta t^{\text{order}+1}\).

The second-order formula is

\[e^{-i H t} \approx \left[ \prod_{j=1}^{m} e^{-i \frac{\Delta t}{2} H_j} \prod_{j=m}^{1} e^{-i \frac{\Delta t}{2} H_j} \right]^n\]

where the Hamiltonian \(H\) is a sum of terms:

\[H = \sum_{j=1}^{m} H_j\]

and the Trotter step size is:

\[\Delta t = \frac{t}{n}\]

and each higher order is built from the one below by the Suzuki recursion

\[S_{2k}(\lambda) = [S_{2k-2}(p_k \lambda)]^2 \cdot S_{2k-2}((1 - 4p_k)\lambda) \cdot [S_{2k-2}(p_k \lambda)]^2\]

with:

\[p_k = \left(4 - 4^{1/(2k - 1)}\right)^{-1}.\]

Each order is declared once as a gate named suzukitrotter_<order>, the higher ones calling the lower ones five times. The circuit gets steps calls to the gate of the requested order.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

  • order (int) – The order of the formula, an even integer of at least 2 (default 2).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian, or order is not an even integer of at least 2.

See also

push_lietrotter(), push_yoshidatrotter(), GateDecl

References

  • M. Suzuki, “General theory of fractal path integrals with applications to many-body theories and statistical physics”, J. Math. Phys. 32, 400 (1991).

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("XX"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * XX @ q[0,1]
>>> c.push_suzukitrotter(h, (0, 1), t=1.0, steps=5, order=2)
2-qubit circuit with 5 instructions:
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
└── suzukitrotter_2(0.2) @ q[0:1]
push_yoshidatrotter(h, qubits, t, steps, order=4)

Append the time evolution under a Hamiltonian with a Yoshida product formula.

Called as a method, circuit.push_yoshidatrotter(h, qubits, t, steps, order). It approximates \(e^{-iHt}\) by composing second-order Trotter formulas symmetrically, which cancels the error terms up to the given even order. Each order makes three calls to the order below, against five for push_suzukitrotter().

The order \(2(k+1)\) formula is built from the order \(2k\) one as

\[S_{2(k+1)}(t) = S_{2k}(w_1 \cdot t) \cdot S_{2k}(w_2 \cdot t) \cdot S_{2k}(w_1 \cdot t)\]

where the weights are:

\[w_1 = \frac{1}{2 - 2^{1/(2k+1)}}, \quad w_2 = -\frac{2^{1/(2k+1)}}{2 - 2^{1/(2k+1)}}\]

and the base case is the standard second-order Strang splitting:

\[S_2(\Delta t) = \prod_{j=1}^{m} e^{-i \Delta t H_j / 2} \prod_{j=m}^{1} e^{-i \Delta t H_j / 2}\]

Each order is declared once as a gate named yoshida_<order>. The circuit gets steps calls to the gate of the requested order.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

  • order (int) – The order of the formula, an even integer of at least 2 (default 4).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian, or order is not an even integer of at least 2.

See also

push_suzukitrotter(), push_lietrotter(), GateDecl

References

  • H. Yoshida, “Construction of higher order symplectic integrators”, Phys. Lett. A 150, 262 (1990).

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("XY"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * XY @ q[0,1]
>>> h.push(0.5, PauliString("Z"), 0)
2-qubit Hamiltonian with 2 terms:
├── 1.0 * XY @ q[0,1]
└── 0.5 * Z @ q[0]
>>> c.push_yoshidatrotter(h, (0, 1), t=1.0, steps=3, order=4)
2-qubit circuit with 3 instructions:
├── yoshida_4(0.3333333333333333) @ q[0:1]
├── yoshida_4(0.3333333333333333) @ q[0:1]
└── yoshida_4(0.3333333333333333) @ q[0:1]
class Instruction(operation, qubits=None, bits=None, zvars=None)[source]

Bases: object

An operation together with the qubits, bits and z-variables it acts on.

Instructions are the elements of a Circuit. They are usually created by Circuit.push(); build one directly to push it later or to insert it at a given position. An instruction cannot be modified after it is created.

Parameters:

  • operation (Operation) – The operation to apply.

  • qubits (tuple of int) – The target qubits, as many as operation.num_qubits. Defaults to ().

  • bits (tuple of int) – The target classical bits, as many as operation.num_bits. Defaults to ().

  • zvars (tuple of int) – The target z-variables, as many as operation.num_zvars. Defaults to ().

Raises:

  • TypeError – If operation is not an Operation, or a target group is not a tuple.

  • ValueError – If a target group has the wrong length, an index is negative, or a qubit is repeated. Repeated bits or z-variables are refused too, unless the operation allows them.

Examples

>>> from mimiqcircuits import *
>>> Instruction(GateX(), (0,))
X @ q[0]
>>> # a measurement targets one qubit and one classical bit
>>> Instruction(Measure(), (2,), (0,))
M @ q[2], c[0]
>>> # consecutive targets are shown as a range
>>> Instruction(Barrier(4), (0, 1, 2, 3))
Barrier @ q[0:3]

push(self, operation, *args)

Add an operation or an instruction at the end of the circuit.

The targets are given in order: first the qubits, then the classical bits, then the z-variables, as many of each as the operation acts on. A target can be an integer or an iterable of integers. When some targets are iterables, one instruction is added for each position, zipping the iterables together and repeating the integer targets; the shortest iterable sets the number of instructions.

Parameters:

  • operation (Operation or Instruction) – The operation to add, or an already-built instruction (then no targets are allowed).

  • *args (int or iterable of int) – The targets.

Returns:

The circuit itself, so calls can be chained.

Return type:

Circuit

Raises:

  • TypeError – If operation is not an Operation or an Instruction, or a target is neither an integer nor an iterable.

  • ValueError – If the number of targets does not match the operation, a target index is negative or repeated, or operation is an operator that is not a gate (such as a projector), which can only be used inside other operations.

Examples

Targets can be integers or iterables of integers. An iterable adds one instruction per element.

>>> from symengine import pi

└── H @ q[0]

├── H @ q[0]
└── T @ q[0]

├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
└── H @ q[2]

>>> c.push(GateS(), 0)
3-qubit circuit with 5 instructions:
├── H @ q[0]
