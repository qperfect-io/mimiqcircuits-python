mimiqcircuits.backends.backend¶

Abstract base classes for simulator backends.

This module defines the contract every simulator must satisfy:

  • Backend — the common interface, advertising identity, capabilities, limits, topology, and an execute() entry point.

  • LocalBackend — for in-process simulators. Adds build_state(), compile(), evolve(), and a default execute() loop built on top of them.

  • RemoteBackend — for cloud or submit/poll execution. Adds submit() and provides a default execute() that waits on the returned job.

See Implementing a Custom Backend for a step-by-step guide.

class RNGs(shot, noise, trajectory, pass_)[source]¶

Bases: object

Four independent random streams, one per simulation stage.

Keeping the streams separate means that the draws of one stage (for example sampling) do not shift the draws of another (for example noise selection), even when the same execution uses both. LocalBackend.execute() builds one bundle per call from seed or rng and hands each stream to the stage it belongs to. Build one with from_seed() or from_generator().

shot¶

Sampling shots from the final state.

Type:

random.Random

noise¶

Kraus and mixed-unitary noise sampling during LocalBackend.evolve().

Type:

random.Random

trajectory¶

Per-trajectory work, such as LocalBackend.prepare_trajectory() and loss sampling.

Type:

random.Random

pass_¶

Randomised compilation passes, read through PassContext.rng.

Type:

random.Random

Examples

>>> from mimiqcircuits import *
>>> from mimiqcircuits.backends import RNGs

The same master seed always gives the same four streams.

>>> a = RNGs.from_seed(42)
>>> b = RNGs.from_seed(42)
>>> a.shot.random() == b.shot.random()
True

Each stream is seeded differently, so they do not repeat each other.

>>> c = RNGs.from_seed(42)
>>> c.shot.random() == c.noise.random()
False

class State[source]¶

Bases: ABC

Simulation state that a LocalBackend builds and evolves.

A state bundles three registers: the quantum register, in whatever representation the backend uses (state vector, MPS, tensor network, …); the classical-bit register, written by measurements and classical operations; and the z-register of complex values, written by Amplitude, ExpectationValue and similar operations.

Subclasses implement num_qubits, num_bits, num_zvars, amplitude(), sample(), classical_bits and complex_values; they may override expectation(), reset() and get_loss_state(), whose defaults raise NotImplementedError.

See also

LocalBackend, whose example defines a complete state.

abstract property num_qubits: int¶

Number of qubits in the quantum register.

abstract property num_bits: int¶

Number of classical bits in the classical register.

abstract property num_zvars: int¶

Number of complex values in the z-register.

Draw nsamples measurement outcomes of all qubits from the state.

class LossState(n_or_flags)[source]¶

Bases: object

Per-qubit register that records which qubits are lost.

It sits next to the quantum, classical and complex registers of a State. Entry q is True when qubit q has left the system. The register holds no loss policy: the runtime-loss driver (LocalBackend.evolve_with_loss()) is the only code that marks qubits; a state that holds one only creates it, clears it in State.reset(), and returns it from State.get_loss_state().

Parameters:

n_or_flags – The number of qubits, all present, or an iterable of booleans giving the initial flag of each qubit.

lost¶

The flag of each qubit.

Type:

list[bool]

Examples

>>> from mimiqcircuits import *
>>> from mimiqcircuits.backends import LossState

Start with three qubits, all present, then lose qubit 1.

>>> ls = LossState(3)
>>> ls.mark_lost(1)
>>> ls.is_lost(1), ls.any_lost([0, 1]), ls.all_lost([0, 1])
(True, True, False)
>>> ls.reset()
>>> ls.lost
[False, False, False]

class Backend[source]¶

Bases: ABC

Abstract base class for every simulator backend.

Subclasses implement name, version, capabilities() and execute(); they may override limits(), topology(), can_handle(), stochastic_kind(), default_passes(), the pass hooks (fuse_pass(), reorder_pass(), canonical_decompose_pass(), remove_swaps_pass(), simplify_pass()), accepts_pass(), delegates_pass() and expectation().

Most backends subclass one of the two bases below, which implement execute():

  • LocalBackend, when the simulator runs in this process and evolves a State;

  • RemoteBackend, when the simulator runs elsewhere (a cloud service, a job queue) and the backend submits jobs and waits for the results.

See Implementing a Custom Backend for a step-by-step guide.

abstract property name: str¶

Name of the simulator, such as "Mimiq".

It is stored in QCSResults.simulator and used in error messages.

abstract property version: str¶

Version string of the simulator, stored in QCSResults.version.

abstract capabilities()[source]¶

Return the set of features this backend can run.

Each entry is a capability token, normally one of CAPABILITY_VOCABULARY. Declare only what the backend really delivers: can_handle() and the conformance tests rely on it.

Returns:

A set of capability strings.

Return type:

set[str]

limits()[source]¶

Return the numeric limits of this backend.

The default returns Limits(), with every limit unbounded.

topology()[source]¶

Return the qubit connectivity of this backend.

The default returns AllToAll.

can_handle(circuit)[source]¶

Check whether this backend can run circuit.

The default compares circuit with limits() and capabilities(). It returns Inadmissible when the circuit:

  • has more qubits, classical bits or z-variables than max_qubits, max_classical_bits or max_zvars allow;

  • contains a Kraus channel with a LossyOperator (loss decided at run time) and the backend does not declare "loss";

  • contains any Kraus channel, also inside an IfStatement or WhileStatement, and the backend does not declare "noise";

  • has free symbolic parameters and the backend does not declare "parametric".

Otherwise it returns Admissible. It never returns Marginal. Backends with other criteria (bond-dimension estimates, connectivity, gate sets) override it.

Parameters:

circuit – The circuit to check.

Returns:

An AdmissionResult. Use is_admissible() to turn it into a bool.

Return type:

AdmissionResult

stochastic_kind(op_or_instruction)[source]¶

Classify when this backend resolves the randomness of an operation.

The answer depends on the backend as well as on the operation: a mixed-unitary channel is TrajectorySampleable for a backend that draws its branch before evolving, but RuntimeOnly for one that draws it from the live state. The default returns default_stochastic_kind(); backends that handle an operation differently override this.

Parameters:

op_or_instruction – An operation, or an instruction whose operation is classified.

Returns:

A StochasticKind.

Return type:

StochasticKind

default_passes()[source]¶

Return the pipeline this backend wants applied before evolution.

This is the backend’s whole part in circuit preparation: it declares the passes it expects, and execute() adjusts that declaration to match the flags the caller set. The backend never sees the flags; when a flag asks for a pass, the backend builds it through fuse_pass(), reorder_pass(), canonical_decompose_pass(), remove_swaps_pass() or simplify_pass(). A flag finds the pass it acts on by its spec().name, so a pass that no flag names is never removed by one.

Returns:

A PassPipeline. The default is empty.

Return type:

PassPipeline

accepts_pass(p)[source]¶

Return whether this backend can run pass p.

apply_passes() raises UnacceptedPassError for a pass the backend refuses, instead of skipping it. The default accepts every pass.

delegates_pass(p)[source]¶

Return whether this backend runs pass p itself.

For a delegated pass, apply_passes() does not call AbstractPass.apply(); it records a PassResult with metadata={"delegated": True} and leaves the work to the backend’s LocalBackend.compile() or LocalBackend.evolve(). The default delegates nothing.

abstract execute(circuit, *, nsamples=1000, seed=None, rng=None, passes=None, fuse=None, canonicaldecompose=None, reorderqubits=None, remove_swaps=None, simplify=None, reorderqubits_seed=None, callback=None, param_grid=None, strict_pass_order=True)[source]¶

Run circuit on this backend and return its results.

To request specific amplitudes or expectation values, push Amplitude or ExpectationValue instructions into circuit and read them from results.zstates.

The preparation flags (fuse, canonicaldecompose, reorderqubits, remove_swaps, simplify) adjust the backend’s default_passes() instead of replacing them. Each speaks about one kind of pass: None leaves that pass as the backend declared it, False drops it, and any other value replaces it with the pass the backend builds for that flag, or adds that pass when the backend declared none of that kind. So fuse=False means “the backend’s pipeline, without fusion”. A pass that no flag names stays even when every flag is False.

The flags have a fixed order among themselves: remove swaps, simplify, canonical decompose, fuse, reorder. A pass added by a flag goes just before the first declared pass of a kind that runs later, or at the end if there is none. passes are appended after all of that, as given; nothing is deduplicated.

simplify=True rewrites the circuit with simplify_pass() while keeping its unitary exactly: inverse pairs cancel, rotations merge, and one- and two-qubit blocks are resynthesised with fewer gates.

Parameters:

  • circuit – A Circuit or a list of circuits. Local backends also take a SweepExperiment, which runs the circuit once per point of its table.

  • nsamples (int) – Number of shots.

  • seed (int | None) – Integer seed for all randomness of the run. Mutually exclusive with rng; with neither, the backend draws fresh entropy.

  • rng (Random | None) – A random.Random to draw the seed from. It is advanced, so two runs with the same generator differ.

  • passes (PassPipeline | None) – Extra passes to run after the backend’s adjusted pipeline.

  • fuse (bool | None) – Install (True) or drop (False) gate fusion.

  • canonicaldecompose (bool | None) – Install or drop the decomposition into the canonical gate set.

  • reorderqubits (bool | str | None) – Install or drop qubit reordering; a string names the reordering method.

  • remove_swaps (bool | None) – Install or drop SWAP removal.

  • simplify (bool | None) – Install or drop circuit simplification. Off unless set.

  • reorderqubits_seed (int | None) – Seed for the reordering pass. It configures reordering; it does not request it.

  • callback – Called by the backend during evolution, once per step.

  • param_grid (list[dict] | None) – A list of dictionaries, each mapping the circuit’s symbols (or their names) to values, such as [{theta: 0.1}, {theta: 0.2}]. Each dictionary is substituted into circuit with evaluate() and runs as its own execution, with a seed derived from seed or rng, so points are independent and a repeated sweep with the same seed gives the same results. Every dictionary must bind all free symbols. An empty list runs circuit once.

  • strict_pass_order (bool) – On a remote backend that does not declare "pass_order_honored", refuse a non-empty passes instead of submitting it as an unordered set.

Returns:

A QCSResults. A list of circuits gives a list of results in the same order; param_grid or a SweepExperiment gives one result per point (a list of such lists for a list of circuits).

Raises:

  • TypeError – If both seed and rng are given, or a flag has the wrong type (for example fuse=0).

  • NotImplementedError – If param_grid is given to a remote backend that does not support it (such as MimiqRemoteBackend), or a flag asks for a pass the backend cannot build.

  • RemotePassOrderError – See strict_pass_order.

class LocalBackend[source]¶

Bases: Backend

Base class for simulators that run in this process.

Subclasses implement build_state(), compile() and evolve(), plus the Backend identity members; they may override prepare_trajectory(), recompile_per_trajectory(), bind() and compile_progress(), and opt into the runtime-loss driver with uses_loss_driver(), apply_instruction(), sample_kraus() and apply_segment().

In return they inherit execute(), which runs the pass pipeline, splits the trailing measurements off into a classical projection, and then either evolves the circuit once and samples the final state, or evolves one fresh state per shot when the circuit has mid-circuit measurements, noise, or loss.

Examples

A backend for circuits of X and CX gates only. Its state is a single computational basis state, so it is exact and fully deterministic.

>>> from mimiqcircuits import *
>>> from mimiqcircuits.backends import (
...     DefaultCompiledCircuit, ExactFidelity, LocalBackend, State)

The state holds the three registers, and samples by returning its basis state nsamples times.

>>> class BasisState(State):
...     def __init__(self, nq, nb, nz):
...         self.qubits = [0] * nq
...         self.bits = [0] * nb
...         self.zvars = [0j] * nz
...     @property
...     def num_qubits(self):
...         return len(self.qubits)
...     @property
...     def num_bits(self):
...         return len(self.bits)
...     @property
...     def num_zvars(self):
...         return len(self.zvars)
...     @property
...     def classical_bits(self):
...         return BitString(self.bits)
...     @property
...     def complex_values(self):
...         return list(self.zvars)
...     def amplitude(self, bs):
...         return 1.0 + 0j if list(bs) == self.qubits else 0j
...     def sample(self, nsamples, rng=None):
...         return [BitString(self.qubits) for _ in range(nsamples)]

The backend declares what it supports, builds states, and evolves them. compile has nothing to lower here, so it wraps the circuit as it is.

>>> class BasisBackend(LocalBackend):
...     @property
...     def name(self):
...         return "Basis"
...     @property
...     def version(self):
...         return "0.1"
...     def capabilities(self):
...         return {"sampling", "classical_bits", "midcircuit_measure"}
...     def build_state(self, nq, nb=0, nz=0, **kwargs):
...         return BasisState(nq, nb, nz)
...     def compile(self, circuit):
...         return DefaultCompiledCircuit(circuit)
...     def evolve(self, state, compiled, *, rng=None, callback=None,
...                stopped=None):
...         for inst in compiled.source:
...             op, qs = inst.operation, inst.qubits
...             if isinstance(op, GateX):
...                 state.qubits[qs[0]] ^= 1
...             elif isinstance(op, GateCX):
...                 state.qubits[qs[1]] ^= state.qubits[qs[0]]
...             elif isinstance(op, Measure):
...                 state.bits[inst.bits[0]] = state.qubits[qs[0]]
...             else:
...                 raise ValueError(f"unsupported operation {op}")
...         return state, ExactFidelity()

execute does the rest. The final measurements never reach evolve: the driver samples the state and maps the samples to the classical register itself.

>>> backend = BasisBackend()
>>> c = Circuit()
>>> c.push(GateX(), 0)
1-qubit circuit with 1 instruction:
└── X @ q[0]

>>> c.push(GateCX(), 0, 1)
2-qubit circuit with 2 instructions:
├── X @ q[0]
└── CX @ q[0], q[1]

>>> c.push(Measure(), range(2), range(2))
2-qubit, 2-bit circuit with 4 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── M @ q[0], c[0]
└── M @ q[1], c[1]

>>> res = backend.execute(c, nsamples=3, seed=1)
>>> res.cstates
[bs"11", bs"11", bs"11"]
>>> res.fidelities
[1.0]

The default can_handle() rejects what the backend does not declare, such as noise.

>>> noisy = Circuit().push(Depolarizing(1, 0.1), 0)
>>> backend.can_handle(noisy)
Inadmissible(reason="circuit contains a noise channel but backend Basis does not declare the 'noise' capability")

optimize(experiment, initparams=None, *, return_history=False, **kwargs)[source]¶

Minimize a cost read from a parametric circuit by running it on this backend.

At every step the optimizer proposes values for the circuit’s symbols, the circuit is evaluated with them and run with execute(), and the cost is the real part of the mean of z-register zregister over the samples. Push the quantity to minimize into that register, for example with push_expval().

Call it with an OptimizationExperiment, a list of them, or a circuit and a dictionary of initial values for all its symbols plus the experiment’s fields as keywords:

  • optimizer: "BFGS", "LBFGS", "CG", "NELDERMEAD", "NEWTON", "COBYLA" (default) or "CMAES". All but "CMAES" come from scipy.optimize.minimize(); "CMAES" needs the cmaes extra (pip install 'mimiqcircuits[cmaes]').

  • maxiters: iteration limit, or None for the optimizer’s own.

  • zregister: index of the z-register holding the cost (default 0).

  • label: a name for the experiment.

With an experiment these fields come from it, and passing them again is an error. Every other keyword goes to execute() on each evaluation: nsamples, seed, fuse, passes and so on. With a fixed seed every evaluation draws the same random numbers, so a noisy cost does not jump between otherwise equal points.

Parameters:

  • experiment – An OptimizationExperiment, a list of them, or a symbolic circuit.

  • initparams – Initial values when experiment is a circuit; must be None otherwise.

  • return_history – Also keep every evaluated run.

  • **kwargs – Experiment fields (with a circuit only) and execute() options.

Returns:

An OptimizationResults with the lowest-cost OptimizationRun and, with return_history=True, every evaluated run in order. A list of experiments gives a list of results in the same order.

Raises:

  • ValueError – For an unknown optimizer, a zregister the circuit does not have, or a circuit and initial values that do not form a valid experiment.

  • TypeError – If initparams or an experiment field is given together with an experiment.

Examples

A one-qubit backend for circuits of RY gates followed by ⟨Z⟩ measurements. It tracks the rotation angle and writes cos(theta) to the z-register.

>>> from mimiqcircuits import *
>>> from mimiqcircuits.backends import (
...     DefaultCompiledCircuit, LocalBackend, State)
>>> import math
>>> from symengine import symbols
>>> class RYState(State):
...     num_qubits = property(lambda self: 1)
...     num_bits = property(lambda self: 0)
...     num_zvars = property(lambda self: len(self.z))
...     classical_bits = property(lambda self: BitString(0))
...     complex_values = property(lambda self: list(self.z))
...     def __init__(self, nz):
...         self.theta, self.z = 0.0, [0j] * nz
...     def amplitude(self, bs):
...         raise NotImplementedError
...     def sample(self, nsamples, rng=None):
...         return [BitString(1)] * nsamples
>>> class RYBackend(LocalBackend):
...     name = "RY"
...     version = "0.1"
...     def capabilities(self):
...         return {"zvars", "expectation_1q"}
...     def build_state(self, nq, nb=0, nz=0, **kwargs):
...         return RYState(nz)
...     def compile(self, circuit):
...         return DefaultCompiledCircuit(circuit)
...     def evolve(self, state, compiled, *, rng=None,
...                callback=None, stopped=None):
...         for inst in compiled.source:
...             if isinstance(inst.operation, GateRY):
...                 state.theta += float(inst.operation.theta)
...             else:
...                 state.z[inst.zvars[0]] = math.cos(state.theta)
...         return state, 1.0

The cost is ⟨Z⟩ on qubit 0, written to z-register 0. It is lowest, -1, at theta = pi.

>>> theta = symbols("theta")
>>> c = Circuit().push(GateRY(theta), 0)
>>> c.push(ExpectationValue(GateZ()), 0, 0)
1-qubit, 1-zvar circuit with 2 instructions:
├── RY(theta) @ q[0]
└── ⟨Z⟩ @ q[0], z[0]

Start from theta = 0.1. nsamples=1 is enough because the cost is exact.

>>> res = RYBackend().optimize(c, {theta: 0.1},
...                            optimizer="NELDERMEAD", nsamples=1)
>>> best = res.get_best()
>>> round(best.cost, 4), round(best.parameters[theta], 2)
(-1.0, 3.14)

uses_loss_driver()[source]¶

Return whether execute() resolves runtime loss through evolve_with_loss().

Runtime loss comes from Kraus channels with a LossyOperator branch: which qubit is lost depends on the branch that fires. A backend opts in by returning True, implementing apply_instruction() and sample_kraus(), and giving its state a LossState (see State.get_loss_state()). The default returns False.

evolve_with_loss(state, circuit, lossmodel, *, rng=None, callback=None, stopped=None)[source]¶

Evolve circuit on state while resolving qubit loss as it happens.

The lost qubits are tracked in the state’s LossState and interpreted as lower_losses() does. The circuit is walked as alternating runs and loss events: each run of instructions on present qubits goes to apply_segment(), then the loss event after it (Loss, Reload, Check, MeasureCheck, a Kraus channel, or an operation on a lost qubit) is resolved against the live state. execute() calls this once per shot when uses_loss_driver() returns True and the circuit has a loss that can only be resolved while it runs.

Parameters:

  • state – A state from build_state() whose get_loss_state() works.

  • circuit – The prepared circuit.

  • lossmodel – The LossModel that decides how an operation on partly lost qubits is rewritten.

  • rng – The noise generator.

  • callback – Called as callback(i, total) once per instruction of circuit, with i from 1 to total, its length. An instruction dropped because its qubits are lost still counts, so the total doesn’t depend on which qubits are lost.

  • stopped – Accepted for symmetry with evolve(); not used.

Returns:

A tuple (state, fidelity), where fidelity is the product of the per-step fidelity factors.

Base class for simulators that run on a remote service.

Subclasses implement submit(), plus the Backend identity members; they may override execute(). The inherited execute() checks the pass order, calls submit(), and blocks on the returned job’s wait().
