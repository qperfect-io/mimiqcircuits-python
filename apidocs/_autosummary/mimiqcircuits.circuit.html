mimiqcircuits.circuit¶

Circuit class and utilities.

Classes

Circuit([instructions])

An ordered list of instructions acting on qubits, classical bits and z-variables.
class Circuit(instructions=None)[source]¶

Bases: object

An ordered list of instructions acting on qubits, classical bits and z-variables.

Operations are added one at a time with c.push(operation, targets...), which returns the circuit so calls can be chained. The number of qubits, bits and z-variables is not declared up front: it is one more than the largest index used on each register.

Parameters:

instructions (list of Instruction) – Instructions to start with. The list is used as the circuit’s storage, not copied. Defaults to an empty circuit.

Raises:

TypeError – If instructions is not a list, or holds anything other than Instruction objects.

Examples

>>> from mimiqcircuits import *
>>> from symengine import pi

Create a new circuit object

>>> c = Circuit()

Add a GateX (Pauli-X) gate on qubit 0

>>> c.push(GateX(), 0)
1-qubit circuit with 1 instruction:
└── X @ q[0]

Add a Controlled-NOT (CX) gate with control qubit 0 and target qubit 1

>>> c.push(GateCX(), 0, 1)
2-qubit circuit with 2 instructions:
├── X @ q[0]
└── CX @ q[0], q[1]

Add a Parametric GateRX gate with parameters pi/4

>>> c.push(GateRX(pi / 4),0)
2-qubit circuit with 3 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
└── RX((1/4)*pi) @ q[0]

Add a Reset gate on qubit 0

>>> c.push(Reset(), 0)
2-qubit circuit with 4 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── RX((1/4)*pi) @ q[0]
└── Reset @ q[0]

Add a Barrier gate on qubits 0 and 1

>>> c.push(Barrier(2), 0, 1)
2-qubit circuit with 5 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── RX((1/4)*pi) @ q[0]
├── Reset @ q[0]
└── Barrier @ q[0:1]

Add a Measurement gate on qubit 0, storing the result in bit 0.

>>> c.push(Measure(), 0, 0)
2-qubit, 1-bit circuit with 6 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── RX((1/4)*pi) @ q[0]
├── Reset @ q[0]
├── Barrier @ q[0:1]
└── M @ q[0], c[0]

Add a Control gate with GateX as the target gate. The first 3 qubits are the control qubits.

>>> c.push(Control(3, GateX()), 0, 1, 2, 3)
4-qubit, 1-bit circuit with 7 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── RX((1/4)*pi) @ q[0]
├── Reset @ q[0]
├── Barrier @ q[0:1]
├── M @ q[0], c[0]
└── C₃X @ q[0:2], q[3]

Add a 3-qubit Parallel gate with GateX

>>> c.push(Parallel(3,GateX()),0, 1, 2)
4-qubit, 1-bit circuit with 8 instructions:
├── X @ q[0]
├── CX @ q[0], q[1]
├── RX((1/4)*pi) @ q[0]
├── Reset @ q[0]
├── Barrier @ q[0:1]
├── M @ q[0], c[0]
├── C₃X @ q[0:2], q[3]
└── ⨷ ³ X @ q[0], q[1], q[2]

To add operations whose size depends on the targets, such as QFT, give the targets as registers with emplace().

Note

Commonly used operations include the single-qubit gates GateX, GateY, GateZ, GateH, GateS, GateT, GateSX, GateID, GateU, GateP, GateRX, GateRY and GateRZ; the two-qubit gates GateCX, GateCY, GateCZ, GateCH, GateSWAP, GateISWAP, GateCS, GateCSX, GateECR, GateDCX, GateCU, GateCP, GateCRX, GateCRY, GateCRZ, GateRXX, GateRYY, GateRZZ, GateXXplusYY and GateXXminusYY; custom gates (GateCustom); the wrappers Control, Parallel, Power and Inverse; the generalized gates QFT and PhaseGradient; Measure and Reset; and Barrier.

property instructions¶

Read-only view of the circuit’s instructions.

The list is the circuit’s own storage, exposed for reading and iteration. Add or remove instructions through push(), insert(), append(), or remove(): these keep the cached dependency graph and resource counts consistent, whereas mutating the returned list in place would silently bypass that bookkeeping.

dag()[source]¶

Return the circuit’s dependency graph as a CircuitDAG.

The graph is built on first use and cached. Changing the circuit through push(), insert(), append() or remove() drops the cache, so the next call rebuilds it.

Returns:

The graph whose vertex i is instruction i.

Return type:

CircuitDAG

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> _ = c.push(GateH(), 0)
>>> _ = c.push(GateCX(), 0, 1)
>>> _ = c.push(GateX(), 1)
>>> # each instruction depends on the previous one on a shared qubit
>>> c.dag().edges()
[(0, 1), (1, 2)]

getparams()[source]¶

Return the parameters of every instruction, in circuit order.

Numeric and symbolic parameters are both returned, one entry per parameter of each operation, so a value can appear more than once.

Returns:

The parameters of all instructions, concatenated.

Return type:

list

Examples

>>> import mimiqcircuits as mc
>>> from symengine import symbols
>>> theta = symbols("theta")
>>> c = mc.Circuit().push(mc.GateRX(theta), 0).push(mc.GateP(0.5), 1)
>>> c.getparams()
[theta, 0.5]
listvars()[source]¶

List the symbolic variables of all the instructions of the circuit.

Operations inside a Block or a wrapper such as Control are included. Variables already substituted by evaluate() are not listed.

Returns:

Each symengine.Symbol once, in no particular order. The list is empty when the circuit has no symbolic parameters.

Return type:

list

Examples

>>> from mimiqcircuits import *
>>> from symengine import Symbol
>>> theta, phi = Symbol("theta"), Symbol("phi")
>>> c = Circuit()
>>> c.push(GateRX(theta), 0)
1-qubit circuit with 1 instruction:
└── RX(theta) @ q[0]

>>> c.push(GateRZ(phi), 1)
2-qubit circuit with 2 instructions:
├── RX(theta) @ q[0]
└── RZ(phi) @ q[1]

>>> sorted(c.listvars(), key=str)
[phi, theta]
>>> c.evaluate({theta: 0.1}).listvars()
[phi]

Return the number of z-variables of the circuit.

empty()[source]¶

Return True if the circuit has no instructions.

push(operation, *args)[source]¶

Add an operation or an instruction at the end of the circuit.

The targets are given in order: first the qubits, then the classical bits, then the z-variables, as many of each as the operation acts on. A target can be an integer or an iterable of integers. When some targets are iterables, one instruction is added for each position, zipping the iterables together and repeating the integer targets; the shortest iterable sets the number of instructions.

Parameters:

  • operation (Operation or Instruction) – The operation to add, or an already-built instruction (then no targets are allowed).

  • *args (int or iterable of int) – The targets.

Returns:

The circuit itself, so calls can be chained.

Return type:

Circuit

Raises:

  • TypeError – If operation is not an Operation or an Instruction, or a target is neither an integer nor an iterable.

  • ValueError – If the number of targets does not match the operation, a target index is negative or repeated, or operation is an operator that is not a gate (such as a projector), which can only be used inside other operations.

Examples

Targets can be integers or iterables of integers. An iterable adds one instruction per element.

>>> from mimiqcircuits import *
>>> from symengine import pi
>>> c = Circuit()
>>> c.push(GateH(), 0)
1-qubit circuit with 1 instruction:
└── H @ q[0]

>>> c.push(GateT(), 0)
1-qubit circuit with 2 instructions:
├── H @ q[0]
└── T @ q[0]

>>> c.push(GateH(), [0,2])  # one H on each of qubits 0 and 2
3-qubit circuit with 4 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
└── H @ q[2]

>>> c.push(GateS(), 0)
3-qubit circuit with 5 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
├── H @ q[2]
└── S @ q[0]

>>> c.push(GateCX(), [2, 0], 1)  # controls 2 and 0, target 1 each time
3-qubit circuit with 7 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
├── H @ q[2]
├── S @ q[0]
├── CX @ q[2], q[1]
└── CX @ q[0], q[1]

>>> c.push(GateH(), 0)
3-qubit circuit with 8 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
├── H @ q[2]
├── S @ q[0]
├── CX @ q[2], q[1]
├── CX @ q[0], q[1]
└── H @ q[0]

>>> c.push(Barrier(3), *range(3))  # same as c.push(Barrier(3), 0, 1, 2)
3-qubit circuit with 9 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
├── H @ q[2]
├── S @ q[0]
├── CX @ q[2], q[1]
├── CX @ q[0], q[1]
├── H @ q[0]
└── Barrier @ q[0:2]

>>> c.push(Measure(), range(3), range(3))  # measure qubit i into bit i
3-qubit, 3-bit circuit with 12 instructions:
├── H @ q[0]
├── T @ q[0]
├── H @ q[0]
├── H @ q[2]
├── S @ q[0]
├── CX @ q[2], q[1]
├── CX @ q[0], q[1]
├── H @ q[0]
├── Barrier @ q[0:2]
├── M @ q[0], c[0]
├── M @ q[1], c[1]
└── M @ q[2], c[2]
emplace(op, *regs)[source]¶

Add an operation at the end of the circuit, with targets given by register.

Each register is a list of indices. An operation has one register for each group of qubits, bits or z-variables it acts on (for example a Control has one register for the controls and one for the targets), given in the order quantum, classical, z-variable. The registers are joined and passed to push().

Operations whose size is still open, such as QFT() or control(GateX()), take their size from the length of the registers. A Parallel takes one single-element register for each qubit.

Parameters:

  • op (Operation) – The operation to add, or a lazy expression that builds it from the register sizes.

  • *regs (list of int) – One list of indices per register.

Returns:

The circuit itself, so calls can be chained.

Return type:

Circuit

Raises:

  • ValueError – If the number of registers or the size of one does not match the operation, or op is an operator that is not a gate.

  • TypeError – If op is not an operation or a lazy expression.

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> # a fixed-size gate takes one register per group of qubits
>>> c.emplace(GateRX(0.2), [0])
1-qubit circuit with 1 instruction:
└── RX(0.2) @ q[0]

>>> # QFT() has no size yet: the register of 3 qubits sets it
>>> c.emplace(QFT(), range(3))
3-qubit circuit with 2 instructions:
├── RX(0.2) @ q[0]
└── QFT @ q[0:2]

>>> # the number of controls comes from the first register
>>> c.emplace(control(GateX()), [0, 1], [2])
3-qubit circuit with 3 instructions:
├── RX(0.2) @ q[0]
├── QFT @ q[0:2]
└── C₂X @ q[0:1], q[2]
insert(index, operation, *args)[source]¶

Insert an operation, an instruction or a whole circuit at a position.

The new instruction is placed before the one currently at index, as with list.insert. Unlike push(), targets must be plain integers, so exactly one instruction is inserted. When operation is a Circuit, all its instructions are inserted in order and no targets are given.

Parameters:

  • index (int) – The position to insert at.

  • operation (Operation, Instruction or Circuit) – What to insert.

  • *args (int) – The target qubits, then bits, then z-variables of operation. Not allowed for an instruction or a circuit.

Returns:

The circuit itself, so calls can be chained.

Return type:

Circuit

Raises:

  • TypeError – If operation is not an operation, an instruction or a circuit, or index is not an integer when inserting a circuit.

  • ValueError – If the number of targets is wrong, a target is invalid, or operation is an operator that is not a gate.

Examples

>>> from mimiqcircuits import *
>>> c= Circuit()
>>> c.push(GateX(), 0)
1-qubit circuit with 1 instruction:
└── X @ q[0]

>>> c.push(GateCX(),0,1)
2-qubit circuit with 2 instructions:
├── X @ q[0]
└── CX @ q[0], q[1]

>>> # put an H between the X and the CX
>>> c.insert(1, GateH(), 0)
2-qubit circuit with 3 instructions:
├── X @ q[0]
├── H @ q[0]
└── CX @ q[0], q[1]

>>> # insert a whole circuit at the start
>>> c.insert(0, Circuit().push(GateZ(), 1))
2-qubit circuit with 4 instructions:
├── Z @ q[1]
├── X @ q[0]
├── H @ q[0]
└── CX @ q[0], q[1]

inverse()[source]¶

Return a new circuit that undoes this one.

The instructions are reversed and each operation is replaced by its inverse. The circuit itself is not changed.

Returns:

The inverse circuit.

decompose(basis=None)[source]¶

Decompose all operations in the circuit to a target basis.

Operations are rewritten recursively until every one is terminal in the basis. The circuit itself is not changed.

Parameters:

basis – The target basis, a DecompositionBasis, or a RewriteRule to apply until it no longer matches. Defaults to CanonicalBasis (GateU and GateCX).

Returns:

A new circuit with every operation in the target basis.

Return type:

Circuit

Examples

Decompose to the canonical basis (the default):

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> c.push(GateH(), 0)
1-qubit circuit with 1 instruction:
└── H @ q[0]

>>> c.push(GateCCX(), 0, 1, 2)
3-qubit circuit with 2 instructions:
├── H @ q[0]
└── C₂X @ q[0:1], q[2]

>>> decomposed = c.decompose()
>>> # every gate is now a GateU or a GateCX
>>> sorted({type(i.operation).__name__ for i in decomposed})
['GateCX', 'GateU']

Decompose to Clifford+T:

>>> from mimiqcircuits import CliffordTBasis

push_expval(hamiltonian, *qubits, firstzvar=None)¶

Append the computation of the expectation value of a Hamiltonian.

Called as a method, circuit.push_expval(hamiltonian, *qubits). For each term \(c_j P_j\) it appends an ExpectationValue of \(P_j\) into z-variable firstzvar + j and scales it by \(c_j\) with Multiply, then sums them all with Add, so that z-variable firstzvar ends up holding

\[\langle \psi | H | \psi \rangle = \sum_j c_j \langle \psi | P_j | \psi \rangle.\]

The other z-variables keep the value of each scaled term. The state is not changed.

Parameters:

  • hamiltonian (Hamiltonian) – The Hamiltonian to evaluate.

  • *qubits (int) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly hamiltonian.num_qubits() of them.

  • firstzvar (int, optional) – First z-variable to use. Defaults to the first unused one, circuit.num_zvars().

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian.

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("ZZ"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * ZZ @ q[0,1]
>>> # Hamiltonian qubits 0 and 1 are circuit qubits 1 and 2
>>> c.push_expval(h, 1, 2)
3-qubit, 1-zvar circuit with 3 instructions:
├── ⟨ZZ⟩ @ q[1:2], z[0]
├── z[0] = 1.0 * z[0]
└── z[0] = 0.0 + z[0]

ExpectationValue, Multiply, Add

push_lietrotter(h, qubits, t, steps)¶

Append the first-order (Lie-Trotter) time evolution under a Hamiltonian.

Called as a method, circuit.push_lietrotter(h, qubits, t, steps). It approximates \(e^{-iHt}\), for \(H = \sum_{j=1}^m c_j P_j\), by

\[e^{-i H t} \approx \left[ \prod_{j=1}^m e^{-i c_j P_j \Delta t} \right]^n,\]

with \(n\) = steps and \(\Delta t = t / n\). The error per step is of order \(\Delta t^2\) and vanishes when the terms commute.

One step is declared once as a gate named trotter with parameter \(\Delta t\), holding one Pauli rotation per term (GateRX, GateRZZ, RPauli, …). The circuit gets steps calls to it.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian.

See also

push_suzukitrotter(), push_yoshidatrotter(), GateDecl

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("ZZ"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * ZZ @ q[0,1]
>>> # evolve for t = 1 in 3 steps of 1/3
>>> c.push_lietrotter(h, (0, 1), t=1.0, steps=3)
2-qubit circuit with 3 instructions:
├── trotter(0.3333333333333333) @ q[0:1]
├── trotter(0.3333333333333333) @ q[0:1]
└── trotter(0.3333333333333333) @ q[0:1]
push_suzukitrotter(h, qubits, t, steps, order=2)¶

Append the time evolution under a Hamiltonian with a Suzuki-Trotter formula.

Called as a method, circuit.push_suzukitrotter(h, qubits, t, steps, order). It approximates \(e^{-iHt}\) with the Suzuki product formula of the given even order, whose error per step is of order \(\Delta t^{\text{order}+1}\).

The second-order formula is

\[e^{-i H t} \approx \left[ \prod_{j=1}^{m} e^{-i \frac{\Delta t}{2} H_j} \prod_{j=m}^{1} e^{-i \frac{\Delta t}{2} H_j} \right]^n\]

where the Hamiltonian \(H\) is a sum of terms:

\[H = \sum_{j=1}^{m} H_j\]

and the Trotter step size is:

\[\Delta t = \frac{t}{n}\]

and each higher order is built from the one below by the Suzuki recursion

\[S_{2k}(\lambda) = [S_{2k-2}(p_k \lambda)]^2 \cdot S_{2k-2}((1 - 4p_k)\lambda) \cdot [S_{2k-2}(p_k \lambda)]^2\]

with:

\[p_k = \left(4 - 4^{1/(2k - 1)}\right)^{-1}.\]

Each order is declared once as a gate named suzukitrotter_<order>, the higher ones calling the lower ones five times. The circuit gets steps calls to the gate of the requested order.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

  • order (int) – The order of the formula, an even integer of at least 2 (default 2).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian, or order is not an even integer of at least 2.

See also

push_lietrotter(), push_yoshidatrotter(), GateDecl

References

  • M. Suzuki, “General theory of fractal path integrals with applications to many-body theories and statistical physics”, J. Math. Phys. 32, 400 (1991).

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("XX"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * XX @ q[0,1]
>>> c.push_suzukitrotter(h, (0, 1), t=1.0, steps=5, order=2)
2-qubit circuit with 5 instructions:
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
├── suzukitrotter_2(0.2) @ q[0:1]
└── suzukitrotter_2(0.2) @ q[0:1]
push_yoshidatrotter(h, qubits, t, steps, order=4)¶

Append the time evolution under a Hamiltonian with a Yoshida product formula.

Called as a method, circuit.push_yoshidatrotter(h, qubits, t, steps, order). It approximates \(e^{-iHt}\) by composing second-order Trotter formulas symmetrically, which cancels the error terms up to the given even order. Each order makes three calls to the order below, against five for push_suzukitrotter().

The order \(2(k+1)\) formula is built from the order \(2k\) one as

\[S_{2(k+1)}(t) = S_{2k}(w_1 \cdot t) \cdot S_{2k}(w_2 \cdot t) \cdot S_{2k}(w_1 \cdot t)\]

where the weights are:

\[w_1 = \frac{1}{2 - 2^{1/(2k+1)}}, \quad w_2 = -\frac{2^{1/(2k+1)}}{2 - 2^{1/(2k+1)}}\]

and the base case is the standard second-order Strang splitting:

\[S_2(\Delta t) = \prod_{j=1}^{m} e^{-i \Delta t H_j / 2} \prod_{j=m}^{1} e^{-i \Delta t H_j / 2}\]

Each order is declared once as a gate named yoshida_<order>. The circuit gets steps calls to the gate of the requested order.

Parameters:

  • h (Hamiltonian) – The Hamiltonian.

  • qubits (tuple) – The circuit qubits that the Hamiltonian qubits 0, 1, ... map to. There must be exactly h.num_qubits() of them.

  • t (float) – The total evolution time.

  • steps (int) – The number of Trotter steps \(n\).

  • order (int) – The order of the formula, an even integer of at least 2 (default 4).

Returns:

The circuit, modified in place.

Return type:

Circuit

Raises:

ValueError – If the number of qubits does not match the Hamiltonian, or order is not an even integer of at least 2.

See also

push_suzukitrotter(), push_lietrotter(), GateDecl

References

  • H. Yoshida, “Construction of higher order symplectic integrators”, Phys. Lett. A 150, 262 (1990).

Examples

>>> from mimiqcircuits import *
>>> c = Circuit()
>>> h = Hamiltonian()
>>> h.push(1.0, PauliString("XY"), 0, 1)
2-qubit Hamiltonian with 1 terms:
└── 1.0 * XY @ q[0,1]
>>> h.push(0.5, PauliString("Z"), 0)
2-qubit Hamiltonian with 2 terms:
├── 1.0 * XY @ q[0,1]
└── 0.5 * Z @ q[0]
>>> c.push_yoshidatrotter(h, (0, 1), t=1.0, steps=3, order=4)
2-qubit circuit with 3 instructions:
├── yoshida_4(0.3333333333333333) @ q[0:1]
├── yoshida_4(0.3333333333333333) @ q[0:1]
└── yoshida_4(0.3333333333333333) @ q[0:1]
